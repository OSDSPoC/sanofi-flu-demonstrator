# Validation report: version 3 (final content fixes)

4 October 2026, against `10_Claude_Code_Final_Content_Fixes.md`. Layout, presenter journey, advisor structure, single header notice and static architecture are unchanged. Nothing was pushed or published.

## What changed

1. **Cluster membership now follows features, not coverage.** A fixed synthetic feature table (`src/data/department_features.json`: access, availability, engagement, recommendation, enhanced-category adoption, plus context fields) is stored separately. Each department is assigned to the nearest of four reference profiles by weighted distance on those five features (equal weights; scales 20 and 10). The assignment code (`src/lib/clustering.mjs`) reads only the features: no coverage, age split, code hash, rural list or existing label. Featured departments keep their agreed vectors and are assigned their agreed profiles by the same method. Counts are now Access-constrained 28, Activation gap 22, Enhanced-vaccine adoption gap 30, Strong delivery 16. Coverage ranges overlap (for example Enhanced 49.0–63.0%, Strong 55.4–66.8%), with five-plus Enhanced/Strong pairs within 0.5 pp of each other. Expected coverage is a separate documented feature rule (featured values fixed). Details, weights and overlap examples: `docs/CLUSTER_RULES.md`.
2. **Opportunity uses real population.** Department 65+ populations come from INSEE's estimate at 1 January 2026 (early results to end 2025), summed from the 65–69 to 95+ bands for all 96 metropolitan departments. The map is "Estimated unvaccinated adults aged 65+" = population 65+ × (1 − 2025–26 coverage), with the population date and coverage season in the legend. Source, file hash and definition are in `src/data/population_65plus.json`, Sources and the docs. The fallback was not needed.
3. **One Action / Owner table.** P2's four actions and owners are a two-column table in the advisor answer, the plan summary and the printed plan (rows stack on narrow screens), per the brief's wording. "Patient-level reminder data stay with providers" moved into the evidence details (and the plan and print notes). P1 and P3 use the same pattern; Commercial's separate Efluelda availability and account investigation stays its own row for P3.

## Not verified or unresolved

- **The interactive print dialog's Cancel button was not exercised.** PDF export used the same print stylesheet in Chrome's engine; a real dialog and Cancel were not driven. Please do one real Save as PDF and one Cancel on the presentation machine.
- **Keyboard and screen-reader use** are designed in but untested with assistive technology. Chrome (headless) is the only browser tried.
- **INSEE figures are early results** (to end 2025), a population estimate rather than an eligible or addressable population, and paired with the 2025–26 coverage season. Definitions are in Sources.
- **Profile quality is by design, not by evidence.** Features, reference profiles and the expected-coverage rule are authored and unvalidated. A few members sit uncomfortably near a profile boundary (for example Tarn, a Strong member with access 63); six departments differ from their expected coverage by more than 6 pp, each flagged in the app as a question to investigate rather than explained with an invented cause.
- **Feature authoring uses a mild tilt towards observed coverage** so the story reads plausibly; this is disclosed in `docs/CLUSTER_RULES.md`. A reviewer who objects can set the tilt to zero in `scripts/author-features.mjs` and regenerate; coverage and profiles would then be unrelated.
- **Removed earlier:** the old 270-answer JSON (version 2) and the unused coverage-threshold rule. They remain in git history.
